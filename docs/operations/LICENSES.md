# Licensing

This page is the practical license map for Mathformer. It is an engineering
inventory, not legal advice. Before a public release, binary distribution, or
dataset redistribution, verify the upstream license files for the exact
versions and artifacts you plan to ship.

## Project License

Mathformer source code, scripts, and documentation are distributed under the
MIT License unless a file explicitly says otherwise. See the top-level
[LICENSE](../../LICENSE).

Most project source and documentation files also carry SPDX headers. New source
files should use the same pattern:

```text
SPDX-License-Identifier: MIT
```

Use `REUSE.toml` only for formats that cannot carry comments (such as JSON and
binaries) and skill Markdown. Scope annotations to explicit files or format-specific
patterns; never cover an entire directory. Keep copyright, license, contributor
credits, and group attribution in native comments for other files, including ordinary
Markdown, shell scripts, and YAML. Preserve shebangs and syntax-sensitive preambles.
For hash-bound source snapshots and proof artifacts, use `.license` sidecars to
preserve their bytes. Symlinks do not need REUSE annotations.
The standalone plugin follows the same policy; its metadata is generated by
`scripts/sync_agent_plugins.py`.

## Python Transitive Inventory

The current Python inventory can be regenerated after activating the environment
you want to inventory:

```bash
python scripts/generate_python_license_inventory.py \
  --output docs/operations/PYTHON_DEPENDENCY_LICENSES.md
```

The generated report reads installed package metadata through
`importlib.metadata`. Treat it as a starting point: installed wheel metadata can
omit bundled native library notices, model licenses, or dataset terms.

## Release Checklist

- Keep the top-level [LICENSE](../../LICENSE) in source distributions.
- Keep external IsarMathLib checkouts outside the release. If packaging them
  separately, retain their upstream copyright and license notices.
- Regenerate the [Python dependency license inventory](PYTHON_DEPENDENCY_LICENSES.md)
  after changing Python extras or lock/resolution state.
- Re-check `.lake/packages/*/LICENSE` after `lake update`.
- If building ProofWidgets frontend assets, generate a separate npm license
  inventory from `.lake/packages/proofwidgets/widget/package-lock.json`.
- Include upstream notices for any redistributed binary wheels, proof assistant
  packages, or external executables.
- Do not redistribute downloaded datasets or paper corpora unless their source
  licenses allow it.

## Software Disclosure Checks

The local disclosure policy is recorded in `.idiap-sd/config.json`. The
`.idiap-sd/` directory is ignored by Git; prepare it with the `idiap-sd` skill
before running `./check.sh` in a fresh checkout. It maps Git author aliases to
Andre Freitas and Danilo Gusicuma and checks contributors per path, independently
of REUSE. The 5 MiB threshold applies to tracked repository files;
local caches and ignored downloads are outside the distribution. No tracked
file exceeded that threshold during preparation, so no LFS migration was needed.

Install the locked development environment and the runtime profiles before
running the disclosure gate:

```bash
uv sync --locked --all-extras --group dev
./check.sh
```

The gate runs pytest, Ruff, Black, Pyright, Vulture, the receipt and reasoning-dashboard HTML rendering
regressions, REUSE, and the attribution/LFS audit. It collects failures and returns
a nonzero status if any check fails. There is no tracked frontend package;
the HTML rendering regressions cover the authored UI output. Ignored PRISM
exports and the Lake dependency cache are not frontend packages for this gate.

SPDX comment headers are required wherever the native format supports comments,
including PRISM (`#`), Lean (`--`), Isabelle/Rocq (`(* ... *)`), and generated
source. Existing sidecars are migrated without dropping attribution. Vendored
IsarMathLib is installed externally; its upstream copyright and BSD-3-Clause
license remain with that separate checkout.

Sidecars remain for JSON/JSONL, plain text without a comment grammar, binary
files, and symlinks. The imported adoption kit under
`docs/migrations/portable-repository-adoption/upstream-v1.2/` is MIT with André
Freitas as copyright holder, as confirmed by the repository owner. Its six
comment-capable files retain sidecars to preserve the upstream transfer manifest.
The 35 proof files bound to artifact hashes in
`libraries/MathformerPhysicsLib/MANIFEST.json` also retain their original bytes.
Each such exception records a file-specific reason and manifest reference in
`.idiap-sd/config.json`; generated status alone is not an exception.

The migration record in `.idiap-sd/header-migration.json` records before/after
source hashes. Migration preserves every preexisting source line and SPDX credit;
all 509 PRISM sources have identical executable token streams before and after.
Only their active generated-source hash inventories are refreshed. The proof
registry, original input fingerprints, and immutable invocation records are
preserved. The license texts in `LICENSES/` come from the SPDX license list.

To update attribution after adding files or contributors, review the relevant
Git history and policy overrides, then run:

```bash
python3 .idiap-sd/idiap_sd.py apply
```

Review and stage the generated metadata. If the policy adds LFS tracking, also
run `git add --renormalize .`; this updates the index without rewriting history.
