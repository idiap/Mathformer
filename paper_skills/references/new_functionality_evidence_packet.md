# New Functionality Evidence Packet

Use this packet before revising either Mathformer paper. The packet is the
bridge from "a feature exists" to "a manuscript claim is justified."

## Required Fields

| Field | Meaning |
| --- | --- |
| `feature_name` | Short name of the new capability. |
| `feature_summary` | One paragraph describing what changed. |
| `implementation_paths` | Repository files implementing the feature. |
| `generated_artifacts` | Reports, dashboards, figures, logs, or proof files produced by the feature. |
| `validation_commands` | Commands used to check the feature or its artifacts. |
| `validation_outputs` | Paths or summaries for the resulting validation evidence. |
| `supported_paper_claims` | Claims the evidence can support. |
| `explicit_non_claims` | Claims the evidence must not be used to support. |
| `target_paper_sections` | Manuscript sections that may need revision. |
| `figure_table_implications` | New or changed figures and tables. |
| `limitations_and_blockers` | Known gaps, missing tools, missing artifacts, or scope limits. |

## Claim Discipline

Each supported claim should name its evidence type:

- `implemented`: backed by local source code.
- `generated`: backed by an artifact emitted by a script or workflow.
- `validated`: backed by a command result or checker.
- `inspected`: backed by a human-readable projection such as HTML or Markdown.
- `conceptual`: useful framing, but not implementation evidence.

Dashboards, plots, and RFDE reports support observability claims. They do not
certify theorem correctness. Backend execution and proof artifacts are separate
evidence surfaces.

## Filled Example: Reasoning-Log HTML Renderer

```yaml
feature_name: Reasoning-log HTML renderer
feature_summary: >
  Converts strict reasoning-log JSONL traces and skill-application traces into
  self-contained HTML dashboards for inspection.
implementation_paths:
  - skills/control/reasoning-log-schema-guardian/scripts/render_reasoning_log_html.py
  - skills/control/reasoning-log-schema-guardian/scripts/validate_reasoning_log.py
generated_artifacts:
  - artifacts/full_autoformalization_reasoning_log_test/reasoning.html
  - artifacts/full_autoformalization_reasoning_log_test/skill_application.html
  - artifacts/full_autoformalization_reasoning_log_test/reasoning.jsonl
  - artifacts/full_autoformalization_reasoning_log_test/skill_application.jsonl
validation_commands:
  - python skills/control/reasoning-log-schema-guardian/scripts/validate_reasoning_log.py --input artifacts/full_autoformalization_reasoning_log_test/reasoning.jsonl --json
  - python skills/control/reasoning-log-schema-guardian/scripts/validate_reasoning_log.py --input artifacts/full_autoformalization_reasoning_log_test/skill_application.jsonl --json
supported_paper_claims:
  - type: dashboard/interface
    claim: Reasoning logs can be projected into a browser-readable inspection surface.
  - type: reasoning-log schema
    claim: Skill-application traces can be validated as structured lifecycle evidence.
explicit_non_claims:
  - The dashboard does not prove mathematical correctness.
  - The dashboard does not replace Lean, Rocq, SymPy, or ATP validation.
target_paper_sections:
  - framework paper: workflow and skill architecture
  - framework paper: observability and demonstrations
  - RFDE paper: measurement projections
figure_table_implications:
  - reasoning-log event lifecycle table
  - observability-stack figure
limitations_and_blockers:
  - Screenshots should be included only when generated by a reproducible path.
```

## Filled Example: Reference-Free Monitor

```yaml
feature_name: Reference-free critic monitor
feature_summary: >
  Tracks the evolution of formalization quality dimensions and emits statistics
  and plots for weakest-dimension targeting.
implementation_paths:
  - skills/rfde/reference-free-critic-monitor/scripts/monitor_reference_free_critics.py
  - skills/rfde/reference-free-critic-monitor/references/reference_free_monitor.md
generated_artifacts:
  - artifacts/reference_free_critic_monitor/platform_refinement_test/evolution/formalization_evolution.csv
  - artifacts/reference_free_critic_monitor/platform_refinement_test/evolution/formalization_evolution.json
  - artifacts/reference_free_critic_monitor/platform_refinement_test/evolution/formalization_evolution.svg
  - examples/outputs/reference_free_monitor_evolution_demo.md
supported_paper_claims:
  - type: reference-free monitor
    claim: The platform can summarize formalization evolution with score deltas, risk deltas, weakest dimensions, blockers, and regressions.
explicit_non_claims:
  - RFDE improvement does not replace backend validation.
  - A monitor plot is diagnosis, not proof.
target_paper_sections:
  - framework paper: reference-free descriptive evaluation
  - RFDE paper: trajectory diagnostics
figure_table_implications:
  - trajectory-diagnostics table
  - backend-validation versus monitor-evidence table
limitations_and_blockers:
  - Monitor statistics should be paired with artifact paths and validation status.
```

## Filled Example: Controlled Workflow Routing

```yaml
feature_name: Controlled action hub
feature_summary: >
  Routes natural-language or explicit workflow requests through registered
  actions with metadata for family, safety, required paths, writes, and command.
implementation_paths:
  - scripts/mathformer.py
  - docs/architecture/AGENTIC_HUB.md
generated_artifacts:
  - artifacts/workflow_hub/
supported_paper_claims:
  - type: workflow-control
    claim: Common workflows can be discovered and executed through controlled repository actions.
explicit_non_claims:
  - The hub does not make arbitrary scripts safe by default.
  - The hub records controlled routing, not theorem correctness.
target_paper_sections:
  - framework paper: repository and workflow evidence
  - framework paper: reproducibility and agent-client setup
figure_table_implications:
  - controlled workflow action table
limitations_and_blockers:
  - New top-level scripts should be registered or explicitly classified as internal helpers.
```
